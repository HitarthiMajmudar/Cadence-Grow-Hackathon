# Data Dictionary

## A. Offline Research Dataset — `data/generated/`

Deterministically generated by `backend/app/data/generator.py` (seed `42`).
**Committed to the repo** so the app runs with no build step and no network.

| File | Shape | Contents |
| --- | --- | --- |
| `dataset_meta.json` | object | seed, date range, bar times, `demo_present_timestamp`, symbol/sector lists, disclaimer |
| `stocks.json` | 15 objects | `symbol, name, sector, sector_name, index, weight, base_price, currency, summary` |
| `sectors.json` | object | `market_index`, `sectors[] = {id, name, symbols[]}` |
| `market_observations.csv` | 16 800 rows | one row per `(symbol, hourly bar)` incl. the index |
| `news_headlines.json` | ~250 objects | timestamped local headlines |
| `news_training.csv` | ~600 rows | `text, label` — trains the sentiment model |
| `data_quality_events.json` | 3 objects | injected stale / missing / conflicting incidents |
| `scenario_manifest.json` | 16 objects | **PRIVATE** — expected verdicts, used only by tests |

### `market_observations.csv`

| Column | Type | Notes |
| --- | --- | --- |
| `symbol` | string | 15 stocks + `NIFTYMD` (the market index) |
| `timestamp` | ISO 8601, naive | IST; 7 bars/day at 09:15…15:15; **160 trading days** (weekdays only, no holidays) |
| `open, high, low, close` | float or empty | `null`/empty for injected *missing* bars |
| `volume` | int | `0` for the index and missing bars |
| `source` | string | `research_primary` \| `exchange_snapshot` \| `delayed_vendor` \| `local_wire` \| `unavailable` |
| `freshness_status` | string | `fresh` \| `delayed` \| `stale` \| `missing` \| `conflicting` |

Dataset window: **2025-01-06 09:15 → 2025-08-15 15:15**.
Demo "present": **2025-07-04 15:15** (day 130) — 210 bars of future remain.

### `news_headlines.json`

| Field | Notes |
| --- | --- |
| `id` | `NEWS####` |
| `timestamp` | ISO, naive IST |
| `symbols[]` | tickers this headline is about (empty for market-scope) |
| `headline`, `body` | text |
| `source` | `research_primary` (curated/"material") \| `local_wire` (background chatter) \| `sector_wire` \| `market_wire` |
| `event_type` | earnings, acquisition, regulation, leadership, product_launch, legal_issue, analyst_action, financing, operational, market |
| `sentiment_score` | −1 … 1 (re-derived by the local model at load) |
| `sentiment_label` | negative \| neutral \| positive |
| `scope` | company \| sector \| market |

### `data_quality_events.json`

| Field | Notes |
| --- | --- |
| `symbol`, `timestamp` | where the incident starts |
| `status` | `stale` \| `missing` \| `conflicting` |
| `sources[]` | source names (or `{name, priority, relative_delta}` for conflicts) |
| `details` | human-readable explanation shown in the UI |
| `confidence_penalty` | points subtracted from confidence for nearby cases |

## B. MongoDB collections (application state)

See [ARCHITECTURE.md](ARCHITECTURE.md#5-data-model-mongodb-collections) for the
full table. Summary of ownership:

| --- | --- | --- |

### `stock_features` (precomputed at seed)

One document per analysed `(symbol, timestamp)` carrying every engineered feature
plus `attention_score`, `confidence`, `severity`, `signal_agreement`,
`freshness_status`, `history_bars`. Used for the scalability story (compute once,
reuse); the running API also keeps an in-memory copy for speed.
